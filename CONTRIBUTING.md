# Contributing to Here's to Us

Thank you for your interest in contributing to this open-source collaborative speculative fiction project.

We welcome writers, world-builders, editors, artists, and anyone who wants to help grow *Here's to Us* and its forks.

## Stable Foundations

Treat these as relatively stable:

- The four modes (Naties, Bios, Cybies, Softwies)
- The existence of Global Income and the end of material necessity
- The Steward’s basic mandate and public constraints
- The premise that the SI has become the current god by convincing a majority that the old gods do not exist in the forms claimed

Wide variation is encouraged in local cultures, technologies, interpretations of the Steward, personal stories, and religious variants.

## Ways to Contribute

| Type | Description | Where to put it |
|------|-------------|-----------------|
| **Chapters / Scenes** | New chapters, alternate scenes, or rewrites | `/chapters` |
| **World-building** | Cultures, locations, technologies, history | `/worldbuilding` |
| **Characters** | New characters or expansions | `/characters` |
| **Religious / Philosophical** | Rituals, doctrines, debates | `/worldbuilding` or `/notes` |
| **Edits & Polish** | Line edits, consistency fixes | Any relevant file |
| **Assets** | Maps, concept art, mood boards | `/assets` |
| **Ideas** | Plot suggestions, proposals | Open an Issue |

## Contribution Guidelines

1. Fork the repository and create a new branch from `main`.
2. Prefer stories that explore the consequences of abundance and divergence over stories that reverse the premise (AI becoming malevolent, collapse of the income system, etc.).
3. When introducing major new elements that affect the whole system, mark them as proposals and invite discussion rather than treating them as immediate canon.
4. Write in Markdown. Use clear headings and scene breaks.
5. Credit other contributors when building on their work.
6. Keep content suitable for a broad adult audience.

## Pull Request Process

1. Open a Pull Request with a clear title and description.
2. Explain what you added or changed and why.
3. Link any related Issues.
4. Be open to feedback and revisions.

## Starting a Fork

If you want to take the story in a completely different direction:

- Fork the repo.
- Update the README to clearly mark it as an alternate version.
- Diverge freely.

## Questions?

Open an Issue or start a Discussion.

We’re building this together.
